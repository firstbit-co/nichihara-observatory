# 09. スプレッドシートで更新する(担当者向け)

お知らせとイベントは、**Google スプレッドシートだけ**で更新します(サイトに出るお知らせ・イベントはすべてシートの行)。GitHub のアカウントは要りません。

- 反映まで:**最大30分ほど**(30分ごとにサイトがシートを読み直す)
- 取り込みの結果:`https://firstbit-co.github.io/nichihara-observatory/admin/status.html`
  (載らなかった行と、その理由が出る)

## 書き方

| シート | 1行に書くこと |
| --- | --- |
| お知らせ | 公開/日付/種類/タイトル/本文/重要 |
| イベント | 公開/開催日/開始/終了/種類/イベント名/ひとことで/料金/本文 |

- **公開** を「公開する」にするとサイトに出る。「下書き」の行は出ない
- 日付は `2026/11/01`、時刻は `19:00` のように書く
- **重要** に ○ を付けたお知らせは、全ページの上に黄色い帯で出る(臨時休館など急ぎのときだけ)
- 直すときはその行を書きかえる。消すときは「下書き」にするか、行を削除する
- 種類は「お知らせ」「イベント」「天文情報」「活動報告」。お知らせページのタブ(`/news/category/notice|event|astronomy|report/`)に分かれて並ぶ。「休館・営業」「道路・アクセス」「メディア」は「お知らせ」タブに入る
- 臨時休館(金曜休館など)は、種類を **休館・営業** にする
- 本文に空行を入れると段落が分かれる。写真は入れられない

**1行目(見出し)とシートの名前(「お知らせ」「イベント」)は変えない**でください。サイトが読めなくなり、更新が止まります(止まっても、公開中のサイトはそのまま残ります)。

## 書き方のきまり

`docs/07-copy-rules.md` と同じ。予約・定員・先着順を書かない/電話での確認をすすめない/料金が変わるとは書かない/「隣の」「日本初」を使わない。
きまりに合わない行は、その行だけサイトに出ず、取り込み結果のページに理由が出る。

## しくみ(管理者向け)

- シートは「リンクを知っている全員:閲覧者」で共有する(載せる内容は公開情報だけ)
- `.github/workflows/deploy.yml` が30分ごとに `scripts/fetch-sheet.mjs` を動かし、シートの行を `src/content/{news,events}/sheet-*.md` に書き出してから公開する(書き出したファイルは git に入れない)
- シートの ID はリポジトリの Variables `SHEET_ID`(なければ deploy.yml の既定値)
- シートが読めないときは公開を止め、今のサイトを残す。GitHub の Actions に赤い×が付くので、共有設定とシート名・見出しを確認する
- 担当者向けの1枚マニュアル:`docs/manual/staff-manual.pdf`(元は同じフォルダの HTML。Chrome で開いて PDF に印刷すれば作り直せる)
- ひな形は `docs/sheet/nichihara-update.xlsx`(作り直しは `python3 docs/sheet/make-template.py`)
- `src/content/news` と `src/content/events` に手で .md を置かない(以前の更新画面 Sveltia CMS は 2026-10-28 に廃止)
